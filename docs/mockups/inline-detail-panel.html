User story

as amaintainer

I wanta workflow that builds and tests every pull request

so thata PR's verdict comes from somewhere other than whichever machine happened to run swift test last

Acceptance criteria5
  1. 1A workflow runs on pull_request targeting main and on push to main.
  2. 2It runs the profile's Build & test commands: swift build then swift test, from ElliotKit.
  3. 3Its pull_request trigger has no branch filter that excludes main.
  4. 4A failing test fails the job, and the failure is readable from the run log without a local checkout.
  5. 5The run completes in a bounded time — a job-level timeout-minutes makes that visible.
Problem

There is no .github/workflows/ in this repository, and branch protection is off (enforcement_level: "off"). Nothing runs when a pull request opens.

Important#18, #19 and #20 — roughly 6 000 added lines — were merged on a local swift test alone.
🧠 Brainstorm 42 lines

Three options were weighed: a hosted runner, a self-hosted mac mini, and no CI with a stricter merge ritual. The hosted runner wins on cost until the suite needs a signed build.
